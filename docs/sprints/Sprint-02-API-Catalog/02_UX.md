# Sprint 02 – API Catalog UX Specification

## UX Vision

The API Catalog module should feel like **Postman meets Linear**—fast, modern, and powerful. Users should understand their entire API surface at a glance, with the ability to drill into details without leaving the workflow.

### Core UX Principles

1. **Progressive Disclosure** – Show summary first, details on demand
2. **Instant Feedback** – Import results visible immediately; no waiting uncertainty
3. **Guided Discovery** – Empty states and onboarding lead users to first import
4. **Keyboard-First** – Search and navigation without mouse
5. **Visual Hierarchy** – Method badges, health indicators, and grouping reduce cognitive load

## 3. Component Library

### 3.1 Import Dropzone

**Component:** `ImportDropzone`

**States:**

- `loading` – Spinner, "Parsing..."

- `error` – Red border, error message

**Component:** `ServiceGroup`

**Props:**
- `service: Service`
- `expanded: boolean`
- `onToggle: () => void`

**Subcomponents:**
- `ServiceHeader` – Name, health badge, operation count, chevron
- `OperationList` – Scrollable list of operations
- `OperationRow` – Method badge, path, summary, health dot

---

### 3.3 Operation Row

**Component:** `OperationRow`

**Props:**
- `operation: Operation`
- `health?: HealthStatus`
- `onClick: () => void`

**Visual:**
- Method badge (left-aligned, color-coded)
- Path with parameter highlighting
- Summary truncated to 80 chars
- Health dot (right-aligned)
- Hover: subtle background tint, cursor pointer

### 3.4 SearchBar

**Component:** `SearchBar`

**Props:**
- `value: string`
- `onChange: (value: string) => void`
- `placeholder: string`
- `debounceMs?: number`

**Behavior:**
- Debounced input (default 150ms)
- Clear button appears when value present
- Focus with `⌘K` / `Ctrl+K` shortcut
- Results dropdown with keyboard navigation

### 3.5 FilterBar

**Component:** `FilterBar`

**Props:**
- `filters: FilterState`
- `onFilterChange: (filters: FilterState) => void`
- `availableMethods: string[]`
- `availableServices: string[]`

**FilterState:**
```typescript
interface FilterState {
  methods: string[];
  services: string[];
  health: string[];
}
```

**Behavior:**
- Multi-select dropdowns with checkboxes
- Active filters shown as removable chips
- "Clear All" button visible when any filter active
- Result count updates live

---

### 3.6 ValidationResult

**Component:** `ValidationResult`

**Props:**
- `result: ParseResult`

**States:**
- `valid` – Green banner, checkmark, count summary
- `warnings` – Yellow banner, warning icon, list of issues with "Proceed" button
- `errors` – Red banner, error icon, list of issues with "Cancel" and "Import Anyway" (if allowed)

## 4. Empty States

### 4.1 No Project Selected

**Trigger:** User lands on `/catalog` without selecting project.

**Message:** "Select a project from the workspace to view its API catalog."

**Action:** [Go to Projects]

### 4.2 Project Has No Catalog

**Trigger:** Project exists but no catalog imported.

**Message:** "No APIs imported yet."

**Actions:**
- [Import APIs] – Opens import dialog
- [Watch Demo] – Opens video modal

**Visual:** Large 📡 icon, format badges

### 4.3 Search Returns No Results

**Trigger:** User searches with no matches.

**Message:** "No endpoints match your search."

**Actions:**
- [Clear Filters]
- [Try Importing APIs] (if catalog empty)

### 4.4 All Endpoints Filtered

**Trigger:** Combined filters exclude all endpoints.

**Message:** "All endpoints filtered out. Adjust your filters."

**Actions:**
- [Clear All Filters]

---

## 5. Error States

### 5.1 Unsupported Format

**Trigger:** User uploads `.txt`, `.pdf`, etc.

**Message:** "Unsupported file format. Please upload OpenAPI, Swagger, Postman, or HAR files."

**Action:** [Choose Another File]

### 5.2 Parse Error

**Trigger:** Spec fails validation.

**Message:** "Unable to parse spec. Found 3 errors."

**Details:**
- Expandable error list with line numbers
- Suggested fixes where applicable

**Actions:**
- [Fix File]
- [View Error Details]

### 5.3 Import Timeout

**Trigger:** File >50MB or URL fetch >30s.

**Message:** "Import timed out. File may be too large or URL unreachable."

**Actions:**
- [Retry]
- [Choose Smaller File]

### 5.4 Health Check Failure

**Trigger:** Endpoint unreachable.

**Message:** "Unable to reach endpoint: POST /v1/payments"

**Details:** Error type (timeout, 5xx, network)

**Actions:**
- [Re-check]
- [Mark as Ignored]

## 6. Accessibility

- **Semantic HTML:** `<nav>`, `<main>`, `<header>`, `<button>`, `<dialog>` for modals
- **Keyboard Navigation:**
  - `⌘K` / `Ctrl+K` – Focus search
  - `Escape` – Close drawer/modal
  - `Enter` – Expand service, open operation
  - `Space` – Toggle service collapse
- **Focus Management:** Focus moves to drawer on open, returns to trigger on close
- **ARIA Labels:**
  - `aria-label` on icon-only buttons
  - `aria-expanded` on collapsible services
  - `aria-live="polite"` for search results count
  - `role="status"` for health indicators
- **Color Contrast:** All text meets WCAG 2.1 AA (4.5:1 minimum)
- **Screen Reader:** Announce search results count, filter changes, health status changes

## 7. Responsive Behavior

| Breakpoint | Layout | Navigation | Catalog |
|------------|--------|------------|---------|
| **>= 1200px** | Full 3-zone | Persistent text | 4-column grid for summary cards |
| **1024-1199px** | Nav icons only | Collapsed icons | 2-column grid |
| **768-1023px** | Single column | Bottom nav | Single column, cards full-width |
| **< 768px** | Stacked | Hamburger menu | Operation rows compact, drawer full-screen |

### Mobile Optimizations

- Service groups stack vertically
- Filters in collapsible drawer
- Search bar sticky at top
- Operation rows show method + path only (hide description)
- Touch targets ≥44px

## 10. User Journey Maps

### 10.1 First Import Journey

1. **Land on Project Workspace** → See "No APIs imported" empty state
2. **Click "Import APIs"** → Import dialog opens
3. **Select File** → Browse and choose `openapi.yaml`
4. **Validation auto-runs** → See "Valid OpenAPI 3.0.3, 24 operations"
5. **Click "Import Catalog"** → Loading spinner, then success toast
6. **Auto-redirect to API Catalog** → See services and operations
7. **Search "payments"** → Filter results in <100ms
8. **Click first operation** → Right drawer opens with details
9. **Press `Escape`** → Drawer closes, focus returns

**Time to value:** <3 minutes

---

### 10.2 Failed Import Recovery

1. **Upload malformed YAML** → Validation shows errors
2. **Review error list** → See "Circular $ref at line 12"
3. **Click "View Error Details"** → Opens raw spec with line highlight
4. **Fix file locally** → Save updated YAML
5. **Re-upload** → Validation passes this time
6. **Click "Import Catalog"** → Success

---

### 10.3 Health Check Journey

1. **Import catalog** → 24 endpoints loaded
2. **Click "Run Health Check"** → Progress modal shows "Checking 24 endpoints..."
3. **Results appear** → Service cards update with health status
4. **See 2 failing endpoints** → Red badges on Inventory service
5. **Click Inventory card** → Catalog filters to show only inventory endpoints
6. **Click failing endpoint** → Drawer shows error details and retry button
7. **Click "Re-check"** → Single endpoint re-probed
8. **See still failing** → Decide to mark as ignored or escalate

## 11. Content Strategy

### 11.1 Microcopy

| Situation | Copy |
|-----------|------|
| Empty catalog | "No APIs imported yet. Import your API collection to begin test generation." |
| Import success | "24 endpoints imported across 3 services." |

| Parse errors | "Import blocked. Found 3 errors that need fixing." |
| Search empty | "No endpoints match your search. Try different keywords or clear filters." |
| All filtered | "All endpoints filtered out. Adjust your filters to see results." |
| Health healthy | "All services healthy. Last checked 2 hours ago." |
| Health degraded | "2 services showing degraded performance. Check API Catalog for details." |
| Health failing | "1 service unreachable. Verify endpoint availability." |

### 11.2 Terminology

| Term | Definition |
|------|------------|
| **Service** | Logical group of endpoints (e.g., "Authentication", "Payments") |
| **Operation** | Single API endpoint (path + method) |
| **Health** | Reachability and latency of live endpoint |
| **Version** | Iteration of imported spec (from `info.version`) |
| **Catalog** | Parsed and validated collection of services and operations |

## 14. Success Criteria

- User completes first import in <3 minutes without documentation
- Search results appear in <100ms
- Service expand/collapse feels instant (<16ms)
- Drawer open/close animation smooth (60fps)
- Error messages actionable (user knows what to fix)
- Empty states guide user to next action
- Keyboard-only users can complete full workflow
- Mobile: all primary actions reachable with thumb
